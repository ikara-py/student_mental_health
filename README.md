# Student Mental Health Risk Prediction

An end-to-end machine learning project that predicts a student's mental health risk level (**Low**, **Medium** or **High**) from lifestyle and academic factors.

The pipeline is orchestrated with **Apache Airflow** (running in Docker), and the trained model is served through a **Streamlit** web app.

> **Disclaimer:** this is an educational project. The predictions are not a medical diagnosis.

---

## Overview

| Step | What happens | Where |
|------|--------------|-------|
| 1. Explore | Data audit and EDA | `notebooks/01_audit_and_eda.ipynb` |
| 2. Prepare | Cleaning, stratified train/test split, outlier capping | `src/student_mental_health/preprocessing.py` |
| 3. Train | Baseline models, then hyperparameter tuning with GridSearchCV | `src/student_mental_health/training.py` |
| 4. Evaluate | Metrics on the held-out test set | `src/student_mental_health/evaluation.py` |
| 5. Orchestrate | Airflow DAG: `prepare_data >> train_model >> evaluate_model` | `dags/student_mental_health_dag.py` |
| 6. Serve | Streamlit app that loads the saved model | `app.py` |

## Dataset

- 2,000 students, 17 columns (`data/raw/student-mental-health.csv`)
- Target: `Mental_Health_Risk` with three balanced classes (High 680, Medium 660, Low 660)
- Features: age, gender, year of study, sleep hours, study hours per week, GPA, social media hours, screen time hours, physical activity, financial stress, family support, attendance rate, part-time job, diet quality, previous mental health history
- Some features contain missing values (sleep, GPA, social media, financial stress, family support, attendance, diet), which the model pipeline imputes

## Modeling

- **Cleaning:** social media hours are capped at screen time hours; `Student_ID` is dropped
- **Split:** 80/20 stratified train/test split with a fixed random seed
- **Preprocessing:** IQR outlier capping (bounds learned on the training set), median imputation + standard scaling for numeric features, most-frequent imputation + one-hot encoding for categorical features
- **Baseline models:** Logistic Regression, Random Forest, SVM
- **Tuning:** `GridSearchCV` with 5-fold `StratifiedKFold`, optimizing weighted F1-score, on Logistic Regression and SVM
- **Final model:** Logistic Regression pipeline, saved to `models/logistic_regression.joblib`
- **Performance:** about 0.75 weighted F1-score on the test set (full metrics are written to `reports/metrics.csv` after each run)

## Quick start

### 1. Clone the repository

```bash
git clone https://github.com/ikara-py/student_mental_health.git
cd student_mental_health
```

### 2. Create the folders and the `docker.env` file

Copy and paste this whole block into your terminal. It creates the folders Airflow writes to and generates a `docker.env` with fresh secret keys and your own user ID, so file permissions just work:

```bash
mkdir -p models reports data/processed logs

cat > docker.env <<EOF
AIRFLOW_UID=$(id -u)
AIRFLOW_EXECUTOR=LocalExecutor
AIRFLOW_LOAD_EXAMPLES=false
AIRFLOW_DAGS_PAUSED=true
AIRFLOW_PORT=8081

POSTGRES_USER=airflow
POSTGRES_PASSWORD=airflow
POSTGRES_DB=airflow
AIRFLOW_DB_CONN=postgresql+psycopg2://airflow:airflow@postgres:5432/airflow

FERNET_KEY=$(python3 -c "import base64,os;print(base64.urlsafe_b64encode(os.urandom(32)).decode())")
AIRFLOW_SECRET_KEY=$(python3 -c "import secrets;print(secrets.token_hex(32))")

AIRFLOW_ADMIN_USERNAME=admin
AIRFLOW_ADMIN_PASSWORD=admin123
AIRFLOW_ADMIN_FIRSTNAME=Admin
AIRFLOW_ADMIN_LASTNAME=User
AIRFLOW_ADMIN_EMAIL=admin@example.com
EOF
```

> `docker.env` contains secrets, so keep it out of version control.

### 3. Start Airflow

```bash
docker compose --env-file docker.env up -d --build
```

The first start builds the image and initializes the database, so give it a minute or two.

### 4. Run the pipeline

1. Open **http://localhost:8081** and log in with `admin` / `admin123`
2. Find the DAG **`student_mental_health_pipeline`** and switch it on (DAGs start paused)
3. Click **Trigger DAG** (the play button)
4. Wait until all three tasks (`prepare_data`, `train_model`, `evaluate_model`) are green

Training includes a grid search, so the `train_model` task takes a few minutes.

When it finishes you will have:

- `data/processed/train.csv` and `data/processed/test.csv`
- `models/logistic_regression.joblib`
- `reports/metrics.csv`

### 5. Launch the Streamlit app

```bash
uv sync
uv run streamlit run app.py
```

Open **http://localhost:8501**, fill in the student profile and click **Predict**.

The app needs `models/logistic_regression.joblib`, so run the DAG at least once first.

## Stopping and restarting

```bash
# stop the containers (keeps the database)
docker compose --env-file docker.env down

# start again
docker compose --env-file docker.env up -d
```

To also delete the Airflow database volume, add `-v` to the `down` command.

## Troubleshooting

**`PermissionError` when a task writes to `models/`, `reports/` or `data/`**
The folders are owned by another user (usually root, because Docker created them). Fix the ownership, then trigger the DAG again:

```bash
sudo chown -R $USER:$USER models reports data logs
```

Make sure `AIRFLOW_UID` in `docker.env` matches your user ID (`id -u`).

**`AttributeError` or version warnings when the app loads the model**
A saved model must be loaded with the same scikit-learn, numpy, pandas and scipy versions that trained it. Print the versions used inside the Airflow container:

```bash
docker compose --env-file docker.env exec airflow-scheduler python -c "import sklearn, numpy, pandas, scipy, joblib; print(sklearn.__version__, numpy.__version__, pandas.__version__, joblib.__version__)"
```

The container currently uses scikit-learn 1.7.2, numpy 1.26.4, pandas 2.1.4, scipy 1.15.3 and joblib 1.5.3. Install exactly these versions locally:

```bash
uv add "scikit-learn==1.7.2" "numpy==1.26.4" "pandas==2.1.4" "joblib==1.5.3"
```

**`ImportError: pyarrow requires NumPy 2.0 or newer`**
This happens when numpy is pinned to 1.26.4 and a newer `pyarrow` is installed. The app avoids charts for this reason; if you add your own charts, try an older `pyarrow` (`uv add "pyarrow<21"`).

**`ModuleNotFoundError: No module named 'dill'`**

```bash
uv add dill
```

**The DAG does not appear in the Airflow UI**
Check the scheduler logs for import errors:

```bash
docker compose --env-file docker.env logs airflow-scheduler
```
